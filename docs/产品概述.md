# FitHub — Product Scope

[English](product-scope.md) · 中文

版本 0.0.4 · 2026-10-06

本文档描述产品定位与功能范围。每个模块都标注了当前实现状态 —— README 里有更详细的现状说明。

## 一句话

FitHub 是一个无需登录即可使用的开源应用发现与直装客户端：把 GitHub Releases 变成一个像应用商店一样好逛的界面，自动解析每个安装包的系统与架构要求，明确告诉你哪一个适合你当前这台设备；如果这台手机上已经装过，它还能扫出来告诉你能不能直接升级、签名是否一致。

## 定位与边界

| 项 | 说明 |
|---|---|
| 品类 | 开源应用发现 + Releases 直装助手 |
| 核心差异 | 设备适配推荐（从一堆 assets 里挑出对的那一个）+ 本机已装扫描 |
| 免登录可用 | 发现、搜索、用户/组织浏览、看 release、解析适配、下载安装 |
| 登录后解锁 | API 配额 60/h → 5000/h（真机验证）、私有仓库（已接线，未验证） |
| 不做 | Issue / PR / 代码浏览、CI Actions、APK 二次打包或破解、广告、推荐算法 |

隐私定位：登录只是为了提高 API 配额，不应成为任何浏览或下载功能的前置条件。

## 功能模块

### 1. 发现

- 三段式结构：热门 / 最近更新 / 精选
- 硬性规则：只展示有真实可下载产物的仓库
- 排序只用客观信号：star 数、最近 release 时间
- Agent 区：按 topic 搜索真实项目，需用户点击触发

状态：**已实现**。GitHub 没有 Trending API，「热门」用 `sort=stars` 代替，UI 上如实标注。

### 2. 统一搜索

一个输入框，仓库 / 用户 / 组织三个结果 Tab。支持 GitHub 搜索语法透传（`has:release`、`language:kotlin`、`topic:compose`），输入防抖 300ms。

**最近搜索**：空查询时排在语法引导前面，上限 10 条，可整体清空。记的是**真正发出去的那一次请求**
（300ms 防抖之后才落一条），不是每次按键 —— 「敲到一半停手」不会被记成用户没打算搜的词。
重复的词**移到最前**而不是追加，所以改词的过程不会在列表里留下两行几乎一样的。
纯本机，**不进 WebDAV**：换设备不该把另一台机器敲过的词搬过来。

状态：**已实现**。

### 3. 用户 / 组织页

头像、bio、followers / following、仓库列表，可按最近更新 / star 排序。

诚实边界：`/search/users` 不返回 followers，因此搜索结果列表里不显示关注者数字 ——「没返回」不等于「是 0」。

状态：**已实现**。

### 4. 仓库详情

Release 列表、产物列表、适配状态标记、仓库元信息。

状态：**已实现**。README 按需加载并用 Markdown 渲染（`GET /repos/{owner}/{repo}/readme` 原文，单文件上限 512 KB）。语言占比条与变更日志高亮尚未实现。

### 5. Release 与适配推荐 ★ 核心

**Step 1 — 识别产物类型**

按扩展名分类：APK / AAB / MSI / DMG / DEB / RPM / tar.gz / zip / exe / 校验文件。

**Step 2 — 深度解析 APK**

- `PackageManager.getPackageArchiveInfo()` —— 零第三方依赖
- 拿到 packageName、versionCode、versionName、minSdk、targetSdk、签名指纹
- `ZipFile` 读 `lib/<abi>/` 与 `split_*.apk`

**Step 3 — 与本机交叉比对**

| 状态 | 呈现 |
|---|---|
| 完全匹配 | 置顶、高亮、主下载按钮 |
| 可降级 | universal 包，说明体积代价 |
| 不匹配 | 置灰但不隐藏，写明原因 |
| 无法解析 | 不猜，标注原因并给原始链接 |

**Step 4 — 预发布控制**（已实现）

「我的 → 默认包含预发布版本」开关，**默认关**：预发布是给愿意尝鲜的人用的，混进「最新版」会让
适配结论指向一个别人还没装的包。GitHub 的 Release 里混进预发布当最新版是真实存在的坑，代码里
`ReleasePick` 与 `ReleasePickTest` 钉住了这条规则。

**Step 5 — 下载与安装**（已实现）

前台服务 + 通知栏进度，下载完成算 SHA-256，交给系统 `PackageInstaller`。SHA-256 只有拿到
**≥32 位权威值**才算「校验通过」，否则界面只说「已算好供你核对」—— 拿自己算的摘要比自己没有意义。
「安装前强制校验」开关默认关，因为多数 Release 不提供校验文件，默认开会让大部分仓库装不了。

状态：Step 1–5 **已实现**。APK 解析由用户在产物行点「解析」触发，不会自动下载。

### 6. 本机已装扫描 ★ 核心

**扫描**：分批读取 `PackageManager.getInstalledPackages(GET_SIGNING_CERTIFICATES)`。

**反向关联 GitHub 仓库**：

1. 用户主动绑定
2. 按包名反查候选仓库

**反查的两条路**（按代价从低到高）：

| 路 | 代价 | 覆盖 |
|---|---|---|
| 随包分发的 F-Droid 索引 | **0 次额外请求**，命中即权威答案 | 只覆盖 F-Droid 收录的应用 |
| 按包名搜候选 → 验 `applicationId` | 候选数 × 路径数 次请求 | 全部 |

F-Droid 索引由 `tools/build-fdroid-index.mjs` 从官方 `index-v2.json` 生成
（源 54.6 MB / 4549 个包 → 筛出 **3698 条 GitHub 映射、186 KB**，打进 assets）。
先查它是因为未登录只有 60 次/小时 —— 走第二条路的话，8 个候选 × 2 个路径就是 16 次请求，
一次反查吃掉 27% 的配额。索引会过期（不上架 / 搬家不通知），命中后仍取不到就退回第二条路。

反查结果只是候选，必须用户确认才写入绑定表 —— 把本机已装的包悄悄认成某个仓库，会报出一个根本不存在的「可升级」。

**内置绑定**：除用户绑定外，`LinkEngine.BUILT_IN_LINKS` 在装载时补一条编译期已知的恒等关系
（`com.heiyehk.fithub → heiyehk/FitHub`）。它不需要反查也不消耗配额 —— 每个装了这个包的人
都不该再走一遍「搜包名 → 看候选 → 点确认」。已有绑定**不覆盖**，用户手动绑到自己的 fork 上
是合法操作；用户解绑内置项会记一枚墓碑，否则每次冷启动都被种回去，变成关不掉的绑定。

**四类核心结论**：

| 结论 | 触发条件 |
|---|---|
| 已是最新 | 本机 versionCode ≥ 最新 release |
| 可升级 | 本机 versionCode < 最新 release |
| 签名冲突 | 两侧证书指纹都读到且不同 —— Android 会拒绝覆盖安装 |
| 版本待确认 | 远端 APK 未解析，versionCode 不可比 |

**包可见性**：Android 11 起有包可见性过滤，不声明 `QUERY_ALL_PACKAGES` 时 `getInstalledPackages` 会静默少返回一批应用。`ScanResult.complete` 记录扫描是否完整，UI 据此区分「共安装 N 个」和「能看到 N 个应用」。

状态：**已实现**。

### 7. 订阅（部分实现）

关注仓库，列表存在本机（`filesDir`），服务器上没有任何记录，因此不需要登录。

- 关注入口：仓库详情页的书签图标
- 元信息以快照形式存本地，订阅页离线可读，打开该页不消耗 API 配额
- 快照超过 6 小时会在行内标注「X 小时前」
- 刷新：行内单个刷新 / 顶部全部刷新，**串行**执行，一次全量刷新 = 关注数次请求
- 导入导出：自家 JSON（非 OPML），走 SAF 选文件；导入默认**合并**，不覆盖本机已有项

未实现：定时检查（WorkManager）、有 release 时的推送通知。WebDAV 同步已实现 —— 需主动开启，按 `exportedAt` 判新旧；只同步订阅，永不带走历史足迹。

### 7.5 历史足迹（已实现）

看过的仓库、解析过的安装包、经 FitHub 安装的应用，记在 `filesDir`。

- **纯本机，永不参与 WebDAV 同步** —— 足迹是设备状态不是账号内容，同步过去会让另一台设备出现本机没发生过的浏览记录
- 同一目标再次发生时并入旧条目并更新时间，不追加重复
- 环形上限 200 条，超出丢最旧
- 设置页「历史足迹」可查看，支持单条清除与整体清空

### 8. 分享（已实现，仅文字版）

系统分享面板，带上仓库、本机适配结论和 Release 链接。是文字不是图片卡片：图片卡片需要
FileProvider + Compose 渲图，而文字版已经带了分享真正值得做的部分 —— **针对你这台设备**的结论。
仓库详情页另有「打开原始 release 链接」把浏览交给系统。

### 9. GitHub OAuth 登录（已实现，真机跑通）

- Device Flow（GitHub 原生支持，无需回调 URI）
- 最小 scope：只申请 `read:user`，不申请 write scope，不做云端同步
- Token 存 `EncryptedSharedPreferences` + Android Keystore
- 读 `X-RateLimit-Remaining` 做 UI 提示
- client_id 是构建期变量（`FITHUB_CLIENT_ID`），不入库；为空时界面直说「没配」而不是首次请求才失败

**哪些验过、哪些没有**：client_id 确实进了 `BuildConfig`，请求真的打到了
`https://github.com/login/device/code`，六种失败状态（没配 client_id、请求失败、用户拒绝、
码过期、`slow_down` 退避）各有各的界面。**完整链路已在真机跑通** —— 设备码 → 浏览器授权 →
轮询换到令牌 → 配额从 60/h 切到 5000/h，令牌落进 Keystore。

**仍未验证的是私有仓库**：那条代码路径接线了，但手头没有真实私有仓库可测，
所以不要把它算作已验证能力。

### 10. 国际化（已实现）

英文与简体中文两种。**英文是默认资源、中文是翻译**，所以非中文系统语言一律回退英文。
App 内覆盖入口在「我的 → 语言」，三选一：跟随系统 / 简体中文 / English；Android 13 及以上它
走的是系统原生 per-app language，所以系统设置里也会出现这一项。

没有引 `androidx.appcompat`：`AppCompatDelegate.setApplicationLocales()` 要求 Activity 继承
`AppCompatActivity` 且主题继承 AppCompat 主题，而本项目主题 parent 是平台主题
`@android:style/Theme.Material.Light.NoActionBar`。`AppLocale` 在 API 33+ 用平台 `LocaleManager`，
以下版本在 `attachBaseContext` 里包装 context。**两条路必须互斥**，否则从系统设置改的语言会被
App 内旧偏好盖回去。

领域层持有资源 ID 而非字符串 —— 详见 README 的「国际化」一节。

## 设计规范

### 风格定位

纯白底、发丝线分隔、单一强调色、20–28dp 圆角、克制的状态色、弹簧动画。层级靠留白和字重建立，颜色只表达状态。

### 配色

当前实现为固定配色，不跟随系统动态取色：

| 令牌 | 值 | 用途 |
|---|---|---|
| surface | `#FEFDFC` | 页面底 |
| hairline | `#E8E6E1` | 分隔线 |
| accent | `#14624F` | 唯一强调色 |
| warn / bad | `#8A5A12` / `#A32B22` | 仅用于警告与签名冲突 |

Material You 动态取色是计划项。

### 排版

- 跟随系统字体（MiSans / HarmonyOS Sans / 思源黑体）
- 版本号、文件体积、校验和统一等宽字体 —— 避免 `1.10 → 1.9` 这类数字宽度变化导致抖动

### 布局

- 卡片圆角 18–20dp，页面左右留白 20dp
- 底部悬浮 tab bar 高 56dp，不通栏

### 动效

| 场景 | 动效 | 参数 |
|---|---|---|
| 详情进入 | 面板右侧滑入，原页面缩小 | spring(damping 0.90, stiffness 420) |
| 列表进场 | 内容上移淡入，逐项 stagger | 位移 16dp，240ms，stagger 24ms |
| 卡片点击 | scale 0.97 回弹 | spring(damping 0.65, stiffness 950) |
| 本机扫描 | 三圈向外 ping | 2400ms 循环 |

只跑 transform / alpha / color，不跑 layout 动画。目标 60/120fps。

### 落地准则

1. 一屏一个决策点 —— 首页只回答「我今天装什么」，详情页只回答「下哪个」
2. 砍掉冗余信息 —— stars/forks/watchers 不占首屏
3. 主操作永远只有一个大按钮
4. 零装饰 —— 不用装饰性插画、不堆渐变、最多一层卡片嵌套
5. 颜色只表达状态，不表达层级
6. 空状态给下一步动作，不写「暂无数据」

## 对标 RepoStore

来源：[F-Droid: com.samyak.repostore](https://f-droid.org/de/packages/com.samyak.repostore)

**沿用**

- 热门 / 最近更新 / 精选三段首页
- 只展示有真实 APK 的仓库
- 无广告、无追踪、开源

**不同**

- RepoStore 只取最新 release 的 assets；FitHub 覆盖全部 release 及每个 release 的适配矩阵
- RepoStore 无本机扫描与签名冲突检测
- RepoStore 以 repo 为中心；FitHub 增加用户 / 组织维度的浏览

**待验证**：两个 App 的实际差异基于 F-Droid 页面描述，未做逐项功能比对。

## 需要提前处理的问题

1. **签名冲突** —— 源码编译的包与已装包签名不同，Android 会拒绝覆盖安装，不显式拦截就是用户数据丢失
2. **API 配额** —— 未登录 60/h，缓存 + 配额提示 + 登录引导
3. **APK 解析失败** —— 部分 APK 加固或非标准打包，解析不了就明说，不猜
4. **私有资产** —— 未授权时 `browser_download_url` 可能是占位符，需要判空
5. **minSdk 不达标** —— 装了但装不上是最差体验，必须在下载前拦
6. **架构误判** —— universal 包在 arm64 上能跑但浪费体积，32 位包在纯 64 位设备上会失败
